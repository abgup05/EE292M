# Session checklists

Quoted from the course's homework slides. Give the reviewer the one that was asked for,
word for word.

## structure (Week 5A, "Order Enables Creativity")

1. The messaging: can a reader say what the project is for, and for whom?
2. The organization: modules with one job each, one pipeline for the data?
3. The design patterns and interfaces this code uses: which patterns, and how do its
   modules talk to each other?
4. One suggestion: how the code could improve.

## message-tests (Week 6A, "Challenge Builds Trust")

1. The message: does the first screen state the one thing a user should take away?
2. The interface: does every mark mean one thing, is one group colored consistently, and
   are unsettled parts marked as drafts?
3. The tests: what is tested and what should be; one unit, one integration, one
   end-to-end and one smoke test, each discussed; one wrong program the tests would pass,
   and one tripwire any error would move.
4. Time and limits: which tests save you time, and what no test can see.

## speed-system (Week 7A, "Design Your System for Your Problem")

1. The speed: where the time goes, from a profile; one change, measured, that changed no
   answer.
2. The system: the drawing in README.md; where each part runs, and how code and data
   reach it.
3. What cannot be rebuilt: the original data, and where the decisions people made are
   kept and backed up.
4. One suggestion: a boundary to add, merge or remove.

## check-in-safety (Week 8A, "Know What You Know, and What You Don't")

1. The check-in, against the plan.
2. CLAUDE.md: what changed this week, and why.
3. The skill: which one ran and why, or which one you should write.
4. Safety nets: what catches a wrong result, what slips past, where the copies are.
5. One suggestion from the reviewer.
