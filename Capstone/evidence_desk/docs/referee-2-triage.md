## Rejected, with a reason

| # | Finding | Reason |
| --- | --- | --- |
| 3, in part | A table row whose figures moved is counted and nothing is shown | True. The parser flattens tables and loses the column headers, so a row cannot be shown as "this cell went from A to B". A table-aware extractor is a piece of work of its own. Stated as a limit |
| 2, in part | A paragraph moved under another sub-heading is "unchanged" | By design: the comparison is within an Item, and a moved paragraph has not changed. The page says "perhaps moved within its Item". What a sub-heading is depends on the filing's typography; that is stated as a limit |
| 6, in part | A quote is verified as present and of a certain length; nothing ties it to the statement; the engine's confidence is ignored | The quote check and the number check are mechanical on purpose and are described as that. Whether a quote bears on a statement is a question of meaning: it goes to the second model and to the reader's accept or reject. A model's confidence is not evidence, so the verdict rule does not read it. The README now says in one line that a quote is verified as present, not as relevant |
| 7, in part | "Revenue fell 56%" passes against a quote that says "up 56%" | Filings write most declines as a positive number with a word ("decreased 56%"), so a sign cannot tell a fall from a rise, and a list of words would guess. Left to the meaning check and the reader, and now named in the README's list of the number check's blind spots and in the function's own description |
| 8 | A run whose verdicts rest on thin evidence can say "complete" | Rejected for the second time: any minimum number of quotes or filings would be arbitrary. But the referee is right that the word invited more than it meant. The README and the rule now say what "complete" means (every stage ran on everything it was given) and that it is not a measure of evidence; the findings and filings behind each verdict are shown per claim |
| — | A line of 59 characters in one filing and 61 in the other is a short line there and a paragraph here | True and rare. Stated as a limit |
| — | The model named in each recording is self-reported; the 28 answer-key values are hand-entered | Both true. The model is the one the session asked the harness for when it started each stand-in; nothing in the repository can prove it. Each answer-key value cites the statement it was read from; a person has not compared them with the statements, which is on my list |
| — | The gate's recorded output names a commit that is not the head | The gate is run on a commit, and its output is committed after it, so the file can only name the commit before. It says which |

## What the referee could not confirm

The live tables need EDGAR as it was on 17 November; the rows are in the evidence file, the filings are not. Two remarks about what NVIDIA added and removed are now quotations from the filings' own paragraphs, which are in the committed sample record (`src/web/sample-changes.json`), not statements about the outside world.

## What this exercise showed

The first finding is a mistake the project's own notes name: a count whose meaning changed between one column and the next. It was in the feature's headline table, in a sentence the session wrote about JPMorgan, on the page and in the report, and 1,094 tests passed over it, because every test checked that the numbers were what the code computed and none asked what the heading said they were. The referee needed no tool to find it, only the patience to read one function and one table together.
