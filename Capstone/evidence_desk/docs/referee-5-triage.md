# The fifth referee, finding by finding (version 14.1)

The referee read version 14 (tag `capstone-v14`, commit `b372c7f`) with read-only tools and ran nothing ([its text, unedited](reviews/referee-5-version-14.md)). Every claim it made about the code was checked against the code at that tag before anything was changed; the file and line given are the tag's. Every fix but one began as a test that failed; the restore check's fix (7b) was written before its tests, which were then run against version 14's `backup.py`, put back for the purpose, and 2 of 24 failed ([`testing.md`](testing.md), "The fifth referee's findings"). Version 14.1 is the answer.

Two things the referee could not see bear on several findings. The gate at version 14 had been run green on a fresh clone (lint, 2,326 offline tests, the smoke test, 337 page assertions and 2 skipped), but no output of it was committed. And the Anthropic API runs are real: credit was added on 18 November, and before that every model answer was a stand-in's recording.

The gate at this version, from a fresh clone: lint, 2,361 offline tests, the smoke test, 337 assertions on the rendered page and 2 skipped (`make verify-fresh`, [`evidence/verify-fresh.txt`](evidence/verify-fresh.txt)).

## What the referee could not confirm, answered

- **2,079 tests and 339 DOM tests, no committed output.** Answered by finding 6: the counts are now the committed run's, 2,361 and 337 with 2 skipped.
- **The three-reader live run and set C through the API.** Their records are in `results/`, which is not committed; the samples are copies, and the readings are in the cassette with `via` naming the API. The README now says which is which.
- **28 published values, a key typed by hand in `tests/test_facts.py`.** True: the key is typed in by hand from each company's Form 10-K (`tests/test_facts.py`, the comment above it says never to edit a value to make a test pass). Nobody else has checked the typing.
- The evaluation counts and the probes are outputs of commands the referee could not run. Each is in the repository beside its command; none was re-derived here.

## What this reading showed

The worst finding was not in the code. Three sentences of the README were true when they were written, on 17 November, and false the next day, when credit was added and the API answered; the new results were added beside them and the old sentences were never reread. The project's own rule, never to report a model-backed result without saying where the answers came from, was kept result by result and broken in the aggregate. One place now says it.

The second was a choice made on purpose and described on purpose: the summariser is shown the findings' verdicts alone, so that recorded requests stay as recorded. That was right for the model; it was applied to the template too, which needs no recording, and the committed example showed the contradiction to anyone who read it. Nobody had.

## Still open after this version

- A model's summary can still say something the verdicts do not; the line after it names what moved, but nothing reads the summary's prose.
- A run finished after a backup still fails the restore check rather than reading as behind.
- Stored spans are not checked again after a parser change; a filing read again is noted only for the later filing.
- A customer share tagged with a segment is offered without saying what it is a share of.
- Nothing of version 14 is timed, and no model-backed run has been.
- A floor for thin evidence, and a rule for banks' cash flows.
- The referee is another Claude model, not an independent party.
