# Triage of the referee's findings

*Week 8B hands-on. The referee's text is in [`reviews/referee-1-version-4.md`](reviews/referee-1-version-4.md), unedited. Every finding is either accepted with a fix or rejected with a reason. The triage was done on 17 November 2026 in the Claude Code session that ran the catch-up; each decision is mine to check.*

The referee read `capstone-v4`. It could not run anything, so each finding came with a way to show it. Where a fix was made, the test named is the referee's own demonstration turned into a test that fails without the fix.

## What the fix for finding 1 did not do

The referee's example was a finding that set company-wide revenue against a claim about China, citing no passage. The fix makes such a finding count only if the second model agrees. When the meaning check was recorded for that run, the second model (Claude Haiku) judged that finding "supported": "shows no company-wide revenue squeeze, so the challenges stance is right". So the rule is in place and tested, and on the referee's own example it changed nothing: the claim is still "mixed". The referee and the session that triaged this think that finding is context at best. Two models of one family thought otherwise. The prompt of the meaning check was not adjusted to make this one case come out differently; that would be fitting the check to its example. What stands behind this now is the reader's reject.

## What the referee could not confirm, and what I did about it

Test counts, the probe table, the backup line and the live walk's output were all cited in the README from files that git ignores. They are now committed under `docs/evidence/` with the command that produced each. The retrieval numbers and the recorded run's counts the referee confirmed from committed files.

## What this exercise showed

The four blind reviews before this one worked from a checklist and found what the checklist asked about. The referee was told only to expect the work to be wrong and to attack the project's own claims, and it found three things no checklist review had: a verdict moved by a finding with no passage, a number check that did not read the sentence beside the one it checked, and a quote that could be labelled with a section it did not come from. All three were in code that had tests, and the tests asserted the behaviour on purpose.
