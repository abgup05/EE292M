## 2. The project in three sentences

Evidence Desk turns one research question and the decision it informs into a brief whose every factual finding links to an exact excerpt from a page the tool actually retrieved. Citations are verified on the server before anything reaches the browser or the Markdown export, and a brief with thin evidence is marked partial rather than presented as complete. The user is a researcher or project lead who needs to see what supports a conclusion, what conflicts with it, and what is still unknown before acting.

(The same three sentences sit at the top of `Capstone/README.md`, revised after the reviews.)

## 3. Stage one: what exists now

The first working slice is built in `Capstone/evidence_desk` on the same stack as the Week 2 app (Python/FastAPI backend, static frontend, Docker Compose on `127.0.0.1:8766`, everything through the Makefile).

- One end-to-end run: question, decision, scope notes, optional seed URLs and a 6–15 source budget; 3–6 subquestions; bounded retrieval (12 s, 2 MB, 180 s run limit, private addresses and unsafe redirects rejected); extraction with section locators and metadata; synthesis; citation verification; a structured brief and a Markdown export.
- Two synthesis backends behind one interface: Claude when a key is configured, otherwise a deterministic extractive mode that only quotes exact sentences. Both pass the same verification gate.
- `make verify` runs lint, 110 offline tests and a live smoke test; `make demo` runs the real seed case.

Measured demo (2026-10-22, Claude backend, no search key): status **partial**; the NIST AI RMF page retrieved with publisher and publication date from metadata; the GAO page refused with HTTP 403 and recorded as a failed source; 4 findings with 4 excerpts, all verified as exact substrings; 2 of 6 subquestions answered. An earlier run exposed an extraction bug that left only the citation block of the NIST page, and the verification gate withheld all 3 of Claude's findings — the intended behaviour, and the reason the bug was found.

Known limits at this stage: public HTML only; no search provider configured, so a run with no seed URLs fails with an explicit error; one page per run is still single-source.
