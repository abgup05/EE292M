## 2. The message

Asked what a first-time user takes away from the first screen, the reviewer said: *"this tool tests each claim in my thesis against the company's own SEC filings, and every verdict opens to the exact passage."* That matches the sentence on the page.

Asked the same of the result screen, it said: *"the takeaway is that something went wrong and nothing was concluded."* The only result a new user can see is the recorded sample, and the sample is the run where every model call was refused: five question marks, an amber banner and the same billing error seven times.

Its first finding goes to what the product claims. The page says a verdict is "computed from quotes checked word for word". The check proves a quote is in the filing. Whether that quote supports the claim is the model's reading, and the page never says so. A "Supported" verdict can rest on a real sentence that does not mean what the finding says.

## 3. The interface

- Amber carries six meanings (a partial run, a rejected field, an over-limit counter, the sample tag, the model-written summary, an unread source), and the ▲ glyph five.
- A dashed border means seven different things. "Not judged" and "not addressed" differ only by dashed against dotted.
- The header says "Engine: claude" on a run where Claude failed at every step.
- The model-written label depends on a regular expression over a string, and only the summary carries it; finding statements written by a model are unmarked.
- "8 passages considered" does not say of how many; "15 findings verified" does not say how many were proposed.

## 4. The tests

One test at each level, and what each would catch:

| Level | Test | What it would catch | What it cannot |
| --- | --- | --- | --- |
| Unit | `test_gate.py::test_locate_with_a_changed_word_is_not_found` | A gate that matches loosely | Anything outside one function |
| Integration | `test_thesis_run.py::test_every_excerpt_is_an_exact_slice_of_the_stored_filing` | An offset that drifts between the parser, the chunker, the index and the gate, on a recorded 10-Q at full size | A filing with a different layout; it only ever sees NVIDIA |
| End to end | `test_api.py::test_a_run_starts_executes_in_the_background_and_is_listed` | Broken wiring between the HTTP layer, the worker thread and the store | The network: EDGAR is a fake. The real end-to-end run is `make demo`, which is not part of the gate |
| Smoke | `tests/smoke.py` | An image that does not start, a page that is not served, bad input that is accepted | Whether a run works; it never starts one |

**Wrong programs the tests would pass.** The reviewer named five, each a specific edit that leaves all 385 tests green:

1. Change `PASSAGES_PER_CLAIM` from 8 to 2. The tests read the constant, so they follow it down.
2. Add "prefer findings that support the claim" to the model prompt. Every engine test mocks the SDK.
3. Set an excerpt's locator from the wrong passage. The only assertion is that the locator is not empty.
4. Swap the ✓ and ✕ glyphs in the page. No test touches the JavaScript.
5. Select the older of two annual reports. The selection tests use one company's index.

A sixth was already known from planning the next version, and it is the most serious: a finding that says "revenue grew 65%" above a quote that says 56%. The quote is exact, so the gate passes it.

**The tripwire.** There is none. The reviewer specified one: run the deterministic engine on the recorded filings with a fixed clock, serialise the run without timestamps or run IDs, and compare it with a checked-in record holding the passage count, the passage IDs offered for each claim, each excerpt's offset, the verdicts, the coverage counts and one SHA-256 of the whole. Any change upstream moves the hash, and the stored intermediate values show which stage moved.

## 5. Time and limits

**Which tests save me time.** The integration test on the recorded 10-Q, because it runs the real parser at the size it ships and takes under a second. The request-rejection tests, because they are the contract with the page.

**Which cost time.** The reviewer found a timing assertion that depends on the machine, exact-string assertions on Markdown, and API tests that exercise the fake EDGAR as much as the code.

**What no test here can see**, in the reviewer's words: whether a highlighted quote actually supports the claim; whether "Open in filing" scrolls to the quote on the live SEC site; whether a newcomer understands the page, and whether colour, contrast and the phone layout hold up; and how the live services behave (real model output, EDGAR limits, billing failures).

## 6. What I decided

| Finding | Decision |
| --- | --- |
| F1: the page overclaims what a verdict rests on | Accept. Reword the first screen and the result. Add a deterministic number check now and a second-model check of meaning in milestone 5 |
| F2: the sample shows no verdict and a wall of errors | Accept. Record a model-backed run and ship that as the sample; report a repeated engine failure once |
| F3: the engine named is not the engine that ran | Accept. The record says which engine answered each claim and how many steps fell back |
| F4, F5: amber, ▲ and dashed borders overloaded | Accept. One meaning per mark, with a legend on the page |
| F6: model-written label incomplete | Accept. Exact comparison, and a badge on every model-written field |
| F7: missing denominators | Accept. The backend counts findings proposed; the page shows "8 of 636" |
| F8: no test of the page | Accept. A headless-browser test that renders a record and checks each verdict's label, glyph and class |
| F9: the Claude engine is tested only against a mock | Accept. Record real responses once and replay them in a test |
| F10: brittle timing and string tests; tests against a fake | Accept the first two. On the third, see `Capstone/README.md`: the fake serves recorded real filings, and the live path stays outside the gate because the gate must pass without a network |
| F11: one company in every pipeline test | Accept. Add a second filer with a different layout |
| F12 and the tripwire | Accept, as specified |
| Wrong programs 1 to 5, and my sixth | Each gets a test that fails on it |
