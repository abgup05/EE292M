## 1. The hands-on: a hostile referee

The four reviews before this one worked from the session's checklist. The referee had no checklist. Its brief, from the lecture's slide with the project's own claims added: you expect this work to be wrong; read the prompt, the README and the code; list the most consequential problems, worst first, each with the file, the line and how you would show it; do not praise; do not fix anything. It could read and search and nothing else, and that limit is enforced by the agent definition, where "do not fix anything" is only advice.

It returned ten findings. Three of them no checklist review had found, and all three were in code with tests that asserted the behaviour on purpose:

1. **A finding with no passage set a verdict.** A finding may cite reported figures instead of a quote. In the recorded run, one such finding, citing company-wide revenue, was the only thing that turned "export controls are restricting revenue" from supported to mixed. Its own reason said the figures "say nothing about China revenue specifically". The README said every verdict opens to an exact filing passage.
2. **The number check read one sentence and not the one beside it.** It checked a finding's statement. A reason saying "grew 65%" above a quote saying 56% passed. It also let "grew 3%" match "(3)%", and it skipped the 3.5 in "senior notes 3.5%" because a pattern meant for "Note 5" ignored case.
3. **A quote could carry the wrong label.** A quote found anywhere in the filing was accepted and shown under the section of the passage the engine had named, so the page could put "Item 1A" over a sentence from Item 3. It could even include a heading line the parser wrote and the filing does not contain.

The rest: a filing with almost nothing under an Item could still give a "complete" run; a count on the page did not add up when a finding was withheld; the note "evidence comes from the company's own filings" was printed on a brief that quoted a page the user had added; "what moved" blamed the filings for a change of engine; the answer key for the figures covered two quantities; and several numbers in the README came from files git ignores.

## 2. Triage: every finding accepted with a fix, or rejected with a reason

The full table is in `docs/referee-triage.md`. In short:

| | Count | Examples |
| --- | --- | --- |
| Accepted with a fix | 16 | A figure-only finding counts toward a verdict only if the second-model check agreed; a quote must lie inside a passage that was offered; the reason is number-checked; a thin filing makes the run partial |
| Rejected with a reason | 5 | Table cells without column headers (the parser's limit, stated); a minimum count of quotes (arbitrary); pinning the DNS answer (a local single-user tool; stated) |

Each accepted fix began as the referee's own demonstration written as a test and seen failing.

One thing was tried and did not work: checking that an "open in filing" link lands on its passage. A headless browser sent to sec.gov was refused as an undeclared automated tool. The link is still unverified in a browser, and that is now the first known limitation.

## 4. New in this version

**Retrieval and generation, scored apart** (`eval/`, thirty cases over five companies):

| | Result |
| --- | --- |
| Retrieval, the claim's own words | The passage that must come back is in the top eight for 9 of 24 answerable cases |
| Retrieval, with the planner's queries | 18 of 24; 21 of 24 in the top twenty |
| Three other rankings, defined before measuring | None beat the planner's queries without losing a case it had. None is wired in |
| Generation: verdict against the expected stance | 20 of 24 answerable cases, and no case where "supports" came back "challenged" or the reverse |
| Generation: unanswerable claims refused | 6 of 6 |
| Quotes that verify | 84 of 84; 67 of 70 numbers matched, and the three that did not withheld two findings |

The expected stances are a model's reading until I have read the cases. The model answers are recorded from a stand-in; the wrapper around these prompts was minimal, with no reminder of the engine's rules.

**A second-model check of meaning.** A different model reads each verified finding with its excerpts and figures, and without the first model's reasoning, and says whether they support the statement. A finding it rejects is withheld. On the recorded NVIDIA run it read 18 findings, agreed with 17, agreed only in part with 1 and withheld none. On the golden set it read 77, agreed with 66, agreed in part with 10 and withheld 1, and it changed no verdict: 20 of 24 before and after.

It also did not do the one thing most wanted from it. The referee's worst finding was a figure-only finding that set company-wide revenue against a claim about China. The fix was that such a finding counts only if the second model agrees. The second model agreed. So the rule exists, is tested, and on the referee's own example changed nothing. The lecture's sentence for this is that a reviewer that agrees by construction has told you nothing; a second model of the same family is not agreement by construction, but it is close enough that it should not be counted as an independent reading.
